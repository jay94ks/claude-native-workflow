# DC-00002 고급(Tier 3) 구현 착수 전 결정

[DS-00001](../design/DS-00001.md) "미확정", [PL-00001](../plan/PL-00001.md)
3단계 7번, [SP-00002](../spec/SP-00002.md)에서 "착수 시점에 결정"으로 미뤄둔
항목들. 실행 착수 전에 확정한다.

## 선택지

**Q1. 호스팅 위치**
- 자체 서버 / AWS / 기타 클라우드 제공자 중 어디에 배포할지.

**Q2. 환경변수·시크릿 관리 방식**
- 예: `.env` + 배포 플랫폼 시크릿 매니저 / Vault류 별도 도구 등.

**Q3. git 웹훅 동기화 대상 호스팅사**
- GitHub / GitLab / 둘 다 지원 중 어디까지 1차로 지원할지
  ([SP-00002](../spec/SP-00002.md) 5절).

**Q4. 지원 DB 우선순위 확정**
- [SP-00001](../spec/SP-00001.md) 6절은 "MySQL 메인 + 오픈소스 DB 대부분"까지만
  정했다. 1차 구현에서 MySQL 다음으로 어떤 순서(MariaDB → PostgreSQL →
  SQLite, 또는 다른 순서)로 지원을 붙일지.

**Q5. 테넌시 모델의 조직 단위 확장 여부**
- [SP-00002](../spec/SP-00002.md) 3절은 프로젝트 단위 테넌시만 MVP 범위로
  정했다. 지금 스키마에 `organizations` 확장 여지를 미리 남겨둘지, 아니면
  전혀 고려하지 않고 나중에 필요해지면 별도 DS로 다시 설계할지.

## 답변 기록

### RP-00005

- 질문 ID: Q1
- 답변일: 2026-09-09

**질문**

클라우드 호스팅 위치는 어디로 할까요?

**답변**

지금은 벤더 중립으로만 설계하고, 실제 배포처는 나중에 정한다. Docker/Docker Compose 기반이라 어떤 컨테이너 호스팅에서도 동작하며, 실제 배포처는 이후 운영 상황(비용/팀 인프라)에 맞춰 확정한다.

### RP-00006

- 질문 ID: Q2
- 답변일: 2026-09-09

**질문**

환경변수/시크릿은 어떻게 관리할까요?

**답변**

dotenv + 배포 플랫폼 기본 시크릿 매니저로 확정. 초기 단계에서 Vault 같은 별도 시크릿 관리 도구는 과잉engineering — 필요해지면 나중에 도입.

### RP-00007

- 질문 ID: Q3
- 답변일: 2026-09-09

**질문**

git 웹훅은 GitHub/GitLab/둘 다 중 어디까지 1차 지원할까요?

**답변**

GitHub만 1차 지원으로 확정. 이 저장소 자신도 GitHub에 호스팅되어 있고 실사용자 다수도 GitHub을 쓸 가능성이 높음. GitLab은 수요가 보이면 이후 추가.

### RP-00008

- 질문 ID: Q4
- 답변일: 2026-09-09

**질문**

MySQL 다음 지원 DB 우선순위는 어떻게 할까요?

**답변**

PostgreSQL → SQLite 순서로 확정. MariaDB는 SP-00002에 이미 명시된 대로 MySQL 커넥터로 호환되어 별도 작업 없이 사실상 지원되므로 우선순위에서 제외. 실제 추가 구현이 필요한 건 PostgreSQL(다른 SQL 방언) 다음 SQLite(가벼운 로컬/개발용).

### RP-00009

- 질문 ID: Q5
- 답변일: 2026-09-09

**질문**

조직 단위 테넌시 확장 여지를 지금 스키마에 남겨둘까요, 나중에 다시 설계할까요?

**답변**

지금은 고려하지 않고, 조직 단위 테넌시가 실제로 필요해지면 별도 DS로 다시 설계한다. SP-00002가 이미 'organizations 테이블을 얹어 확장 가능한 구조로만 남긴다'고 써둔 것과 일치 — 지금 스키마를 미리 넓히지 않는다(YAGNI).
