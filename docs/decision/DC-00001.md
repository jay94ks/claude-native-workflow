## 배경

`docs/PROTOCOL.md`에 따르면 여러 선택지 중 하나를 확정해야 하는 항목은 `DC`로

## 선택지

**Q1. tier2/tier3 폴더 분리 방식**
- A안: `tier2/`와 `tier3/`를 완전히 분리된 폴더로 둔다(코드 중복 발생, 대신
  경계가 명확함).
- B안: `tier2/`를 base로 두고 `tier3/`는 인증·멀티테넌시·클라우드 배포 설정
  차이만 얹는 구조(예: `tier3/`가 `tier2/backend`를 참조/확장).

**Q2. 로컬 API 서버 프레임워크**
- A안: Express
- B안: Fastify

**Q3. git 조작 방식**
- A안: `simple-git`(npm 라이브러리)
- B안: git CLI를 서브프로세스로 직접 호출

**Q4. ORM/쿼리 빌더**
- A안: Prisma
- B안: Knex
- C안: Drizzle

## 답변 기록

### RP-00001

- 질문 ID: Q1
- 답변일: 2026-09-09

**질문**

tier2/tier3 폴더 구조는 A안(완전 분리)/B안(tier2 확장) 중 무엇으로?

**답변**

B안 확정 — tier2를 base로 두고 tier3는 인증/멀티테넌시/클라우드 배포 설정만 얹는 구조로 간다. DS-00001의 "평범/고급은 같은 Node 백엔드 코드베이스를 공유한다"는 원칙과 일치.

### RP-00002

- 질문 ID: Q2
- 답변일: 2026-09-09

**질문**

로컬 API 서버는 Express/Fastify 중 무엇으로?

**답변**

Express로 확정. 가장 넓은 생태계와 문서화, Claude가 코드를 생성할 때도 가장 익숙한 패턴이라 실수가 적음. 이 프로젝트 규모에서 Fastify와의 성능 차이는 무의미.

### RP-00003

- 질문 ID: Q3
- 답변일: 2026-09-09

**질문**

git 조작은 simple-git/서브프로세스 직접 호출 중 무엇으로?

**답변**

simple-git으로 확정. Tier2는 이미 npm 의존성을 허용하는 등급이라 부담이 없고, Promise 기반 래퍼로 commit/push/pull/log/diff 자동화 코드를 짧고 안정적으로 유지할 수 있음.

### RP-00004

- 질문 ID: Q4
- 답변일: 2026-09-09

**질문**

ORM은 Prisma/Knex/Drizzle 중 무엇으로?

**답변**

Prisma로 확정. 스키마 파일로 마이그레이션을 자동 관리하고 타입 안전 클라이언트를 생성 — 이 프로젝트의 '도구가 실수를 구조적으로 막는다'는 철학과 가장 잘 맞음. MySQL/PostgreSQL/SQLite는 공식 지원, MariaDB는 MySQL 커넥터로 호환.
